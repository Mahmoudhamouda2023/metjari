# نتائج فحص متجري 1.5.0

التاريخ: 4 نوفمبر 2026.

## نطاق التنفيذ

- دورة مرتجع مرتبطة بالطلب الأصلي: تسليم المكتب، تأكيد المكتب، إسناد كابتن إرجاع، الاستلام والطريق وتسليم المتجر.
- كشف مرتجعات مع بحث وتصفية وتصدير CSV متوافق مع Excel.
- حفظ كابتن التوصيل وكابتن الإرجاع وتواريخ الحيازة وسجل الأحداث.
- توزيع إجمالي أجور المرتجع بين الكابتنين وفق نسبة محفوظة في الطلب، مع منع تكرار رسوم المتجر.
- إعدادات النقاط، سجل الحركات، حجز الاستبدال، مراجعة الإدارة، إصدار كوبون وحيد مرتبط بالمتجر، وإشعاراته.
- احتساب النقاط مرة واحدة وفق قواعد إنشاء الطلب والتحقق من التحصيل، وعكسها عند تصحيح التحصيل.
- تحديث ضوابط تعطيل الكابتن لمنع تعطيل مهام الإرجاع المفتوحة، في الحزمة الداخلية ونسخة vendor المرفقة.

## التحقق الآلي

- PHP 8.3.6 وLaravel 12 مع الاعتماديات المرفقة.
- مجموعة التطبيق على SQLite: 124 اختبارًا، 711 تحققًا، دون إخفاقات.
- مجموعة التطبيق على MariaDB 10.11.14 باستخدام اتصال Laravel mysql: 123 اختبارًا ناجحًا واختبار واحد متجاوز من إجمالي 124، و707 تحققات. الاختبار المتجاوز يختبر down/up لترحيل تاريخي داخل معاملة SQLite؛ أوامر DDL في MariaDB/MySQL تعتمد ضمنيًا، لذلك لا يُشغّل هذا الاختبار التاريخي هناك. اختبار الترقية الفعلي أدناه منفصل عنه.
- جميع اختبارات الميزات الجديدة، وعددها 17، شُغّلت على المحركين.
- أربع حالات JavaScript للإشعارات نجحت.
- فحص صياغة ملفات PHP، وفحص صياغة JavaScript المعدل، وتجميع قوالب Blade ومسارات التطبيق.
- التحقق من استجابات HTML للصفحات الجديدة على حسابات الإدارة والكابتن والمتجر. لم يُنجز فحص بصري آلي للصفحات داخل متصفح رسومي بسبب عدم توفر ملف متصفح قابل للتشغيل في بيئة الفحص.

## اختبار ترقية بيانات فعلية تجريبية

أُنشئت قاعدة منفصلة بالإصدار 1.4.2، وفيها طلب مكتمل التحصيل وقيده المالي وأحداثه وإشعاراته. طُبقت ترقية 1.5.0 على هذه القاعدة؛ بقي رقم الطلب وقيمته ورسومه ومستحق الكابتن وسجل الأحداث والإشعارات محفوظة، ولم تُضف نقاط للطلب القديم. نجحت التجربة على SQLite وعلى MariaDB.

## حالات الأعمال المغطاة

- منع تخطي تأكيد المكتب ومنع كابتن غير مسند من تسليم المرتجع.
- إعادة الإسناد قبل الاستلام وإلغاء صلاحية كابتن الإرجاع السابق.
- المرتجع مع الكابتن نفسه أو كابتنين، وصرف الأجور وتسوية المتجر دون تكرار.
- الرصيد غير الكافي، والحجز، وطلب متكرر، وموافقة متكررة، والرفض وإعادة إتاحة النقاط.
- تغيير شروط النقاط، وإيقاف النظام، وبقاء شروط الطلب المرسل للمراجعة.
- التحصيل الإلكتروني قبل الموافقة وبعدها، والتصحيح وعكس النقاط وإعادة منحها بعد التحقق.
- كوبون المتجر الواحد، والاستعمال الواحد، والانتهاء، والإلغاء، والإرجاع، ومنع تعديل كوبون المكافأة ككوبون عام.
- عزل حسابات المتاجر والكباتن وصلاحيات التشغيل والمالية.

## حدود التحقق

لم تُستخدم قاعدة بيانات المستخدم أو بيانات عمل حقيقية. اختبار الاتصال mysql أُجري على MariaDB 10.11؛ لم يُشغّل خادم Oracle MySQL 8 منفصل. تغييرات الرصيد محمية بمعاملات وأقفال صفوف المتجر وقيود قاعدة البيانات، لكن لم يُنفذ اختبار ضغط متزامن متعدد الأجهزة. يلزم تشغيل migration على قاعدة المستخدم، ثم تجربة دورة مرتجع ومكافأة في بيئته قبل الاعتماد التشغيلي.
